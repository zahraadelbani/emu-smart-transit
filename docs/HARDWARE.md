# Traccar and tracker commissioning

Verified sources reviewed 2026-11-24: [Traccar documentation](https://www.traccar.org/documentation/), [REST API](https://www.traccar.org/api-reference/), [official OpenAPI](https://github.com/traccar/traccar/blob/master/openapi.yaml), [device matrix](https://www.traccar.org/devices/). The matrix lists **Teltonika FMC920 → teltonika → 5027**. Protocol compatibility is confirmed by that listing; actual university device connectivity has not been tested. The Compose image is pinned; review its release notes/security updates before deployment and run integration smoke tests on the selected release.

1. Obtain transportation/IT approval, choose the cellular region/model, and confirm manufacturer supply voltage, fused wiring, ignition requirements and installation by a qualified vehicle electrician. Do not infer wiring or electrical ratings from a protocol listing.
2. Obtain an activated data SIM whose operator supports the purchased tracker bands and the operational area. Confirm roaming restrictions, data allowance, PIN handling and coverage along each route. Set the operator-provided APN and credentials in the manufacturer's configuration tool. Test internet access; browser-facing HTTPS alone does not make a binary protocol port reachable.
3. Configure the tracker identifier exactly as the device transmits it (typically an IMEI for this protocol, verify on the actual model). Register it in Traccar. Do not use a bus fleet label as an assumed hardware identifier.
4. Configure the approved public tracker hostname, e.g. `gps.emu.edu.tr`, and the selected protocol's TCP port (5027 for the listed FMC920). DNS must resolve externally; allow/forward only the required port. Traccar web/API port 8082 is loopback/private by default. Access the UI through an authenticated SSH tunnel or approved VPN.
5. Start with 5–10 second moving reports and tune stationary reporting with the operator and transportation staff. Align `LIVE_SECONDS` and `OFFLINE_SECONDS` with the actual reporting interval and network latency. Do not label a normally stationary reporting interval as a failure.
6. In Traccar, create a least-privileged integration account restricted to the university devices. Put credentials into backend environment variables. In Smart Transit staff devices, save the numeric Traccar device ID and associate exactly one physical bus. Device identifiers never go to students.
7. Independently survey each line, combined route, direction and stop order. Import/draw those coordinates, configure cumulative route-stop distances and verify them. A spontaneous service can use a named unverified route with assigned lines and no geometry; live location is shown but ETA remains unavailable.
8. Test first outdoors with a clear sky view and safe stationary vehicle, then on an approved real journey. Compare tracker identifier, server log, Traccar position, `fixTime`, course and speed, then worker health and student map. Confirm speed conversion from Traccar knots to km/h. Test GPS signal loss, mobile data interruption, resumed fixes and assignment changes.
9. Choose encryption only after confirming support in the exact tracker firmware/protocol. Enable manufacturer-supported TLS or a private cellular APN/VPN where available. This configuration does not claim raw TCP 5027 is encrypted. Use HTTPS for remote REST traffic and never expose the backend database or Traccar management UI publicly without an approved access layer.

Troubleshooting: check vehicle supply/fuse, SIM activation/PIN, APN, roaming, signal, DNS, NAT/firewall, TCP listener, tracker ID and Traccar logs in that order. A worker with no mapped positions may be healthy while individual buses remain offline: these are different signals. Invalid, future and out-of-order fixes do not replace latest positions. Provider timeouts/backoff never block public map requests. Never switch to simulated data to mask a real outage.

Before purchasing: obtain vendor confirmation of regional LTE service and device firmware/protocol compatibility, installation quote, warranty/support and secure communication options. No trackers or SIMs have been purchased or commissioned as part of this implementation.
